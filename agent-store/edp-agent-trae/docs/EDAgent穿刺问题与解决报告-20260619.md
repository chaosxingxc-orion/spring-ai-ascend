# EDAgent 技术穿刺问题与解决报告

## 1. 报告目的

本文记录 `agent-store/edp-agent-trae` 技术穿刺期间遇到的主要问题、定位过程、根因、解决方法和验证结果。

本轮穿刺围绕以下主链路展开：

```text
stream-debug-ui
  → /api/stream
  → http://localhost:8190/a2a
  → A2aJsonRpcController
  → EdpaRuntimeHandler
  → DeepAgent
  → deepseek-v4-pro
  → A2A JSON-RPC SSE
  → stream-debug-ui SSE 转换
  → 前端展示
```

最终主链路已打通，并完成 P17 内置业务工具注册基础穿刺。

## 3. 详细问题记录

### Q1：`edp-agent-trae/spike` 不是可启动 Web 服务

#### 现象

将服务端口调整为 8190 后，请求无法连接，8190 没有服务监听。

#### 根因

`spike` 模块最初只是穿刺验证代码，不是完整 Spring Boot Web 应用，缺少：

- Spring Boot 启动类
- Web 依赖
- Runtime Handler Bean 注册

#### 解决方法

新增 Spring Boot 启动类：

- `agent-store/edp-agent-trae/spike/src/main/java/com/huawei/ascend/edp/EdpaSpikeApplication.java`

新增 Runtime Handler 配置：

- `agent-store/edp-agent-trae/spike/src/main/java/com/huawei/ascend/edp/EdpaSpikeConfiguration.java`

配置中注册 `EdpaRuntimeHandler` Bean，并调用：

```java
handler.init(yamlPath, configPath);
```

#### 验证结果

服务后续可启动，A2A 请求能够进入 `EdpaRuntimeHandler`。

### Q5：A2A JSON-RPC 请求格式不匹配

#### 现象

`stream-debug-ui` 原有预设只能构造 AS-Agent `/api/chat`、Planning Path 或 `/query/stream` 风格请求体。直接指向 8190 `/a2a` 时，请求体不是 A2A JSON-RPC 格式，后端无法按 A2A 协议解释用户消息。

A2A `/a2a` 期望的请求不是普通：

```json
{
  "query": "帮我推荐几款稳健型理财产品"
}
```

而是 JSON-RPC 2.0 请求：

```json
{
  "jsonrpc": "2.0",
  "method": "SendStreamingMessage",
  "id": "stream-debug-ui-...",
  "params": {
    "message": {
      "role": "ROLE_USER",
      "messageId": "msg-...",
      "contextId": "conv-...",
      "metadata": {
        "userId": "1",
        "agentId": "edp-agent",
        "sessionId": "conv-...",
        "roleName": "mobile-bank",
        "source": "stream-debug-ui"
      },
      "parts": [
        {
          "text": "帮我推荐几款稳健型理财产品"
        }
      ]
    }
  }
}
```

#### 根因

A2A 是 JSON-RPC 协议入口，不是普通聊天 HTTP API。关键协议字段包括：

- `jsonrpc: "2.0"`
- `method: "SendStreamingMessage"`
- `id`
- `params.message.role`
- `params.message.messageId`
- `params.message.contextId`
- `params.message.parts[].text`

前端未提供 A2A 专用 preset 时，代理层无法生成这些字段。

#### 解决方法

在 `stream-debug-ui` 中新增 A2A 预设：

```html
<option value="a2a">A2A (/a2a)</option>
```

并在 `stream-debug-ui/server.js` 中补齐两类逻辑：

1. URL 路由：

```js
if (preset === "a2a") {
  return `${cleanBase}/a2a`;
}
```

2. 请求体构造：

```js
if (preset === "a2a") {
  const convId = String(conversationId || "conv-" + Date.now());
  return {
    jsonrpc: "2.0",
    method: "SendStreamingMessage",
    id: "stream-debug-ui-" + Date.now(),
    params: {
      message: {
        role: "ROLE_USER",
        messageId: "msg-" + Date.now(),
        contextId: convId,
        metadata: {
          userId: "1",
          agentId: "edp-agent",
          sessionId: convId,
          roleName: String(roleName || "mobile-bank"),
          source: "stream-debug-ui"
        },
        parts: [{ text: String(query) }]
      }
    }
  };
}
```

#### 验证结果

前端代理日志出现：

```text
[proxy] http://localhost:8190/a2a
```

请求体中包含：

```json
"method": "SendStreamingMessage"
```

以及：

```json
"parts": [{ "text": "帮我推荐几款稳健型理财产品" }]
```

说明前端已按 A2A JSON-RPC 协议发送请求。

### Q6：`/a2a` 请求返回 HTTP 500

#### 现象

前端显示：

```text
[stream_error] HTTP 500: {"timestamp":"2026-06-19T15:51:24.463Z","status":500,"error":"Internal Server Error","path":"/a2a"}
```

后端异常包含：

```text
IllegalArgumentException: Unrecognized Type: org.springframework.core.ResolvableType$EmptyType
```

#### 根因

`A2aJsonRpcController` 中 `/a2a` 同时存在 JSON handler 和 SSE handler。

前端代理请求没有带：

```http
Accept: text/event-stream
```

导致 Spring 选择了 JSON handler。JSON handler 返回了流式对象，Spring MVC 尝试用 Jackson 序列化 `Flux<ServerSentEvent<String>>`，最终报 500。

#### 解决方法

在 `stream-debug-ui/server.js` 中，A2A 请求增加：

```js
headers: {
  "Content-Type": "application/json",
  "Accept": requestPreset === "a2a" ? "text/event-stream" : "application/json, text/event-stream"
}
```

#### 验证结果

A2A 请求命中 SSE handler，不再出现该 500。

### Q7：缺少 WebFlux 依赖

#### 现象

A2A SSE 处理路径运行不完整，前期请求出现 500。

#### 根因

后端 A2A SSE handler 使用：

```java
Flux<ServerSentEvent<String>>
```

但 spike 模块最初只具备 Web MVC 依赖，缺少 WebFlux 相关运行依赖。

#### 解决方法

在：

- `agent-store/edp-agent-trae/spike/pom.xml`

加入：

```xml
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-webflux</artifactId>
</dependency>
```

#### 验证结果

SSE handler 可运行，A2A 流式响应可返回。

### Q8：前端收到响应但页面不显示

#### 现象

后端日志显示请求已完成：

```text
[A2A] result ... type=COMPLETED
[A2A] task state=COMPLETED
```

前端日志也收到 A2A 原生 SSE：

```text
event:jsonrpc
data:{"jsonrpc":"2.0","result":{"artifactUpdate":...}}
```

但页面没有展示内容。

#### 根因

`stream-debug-ui` 前端渲染逻辑期望的数据结构是：

```json
{
  "success": true,
  "custom_rsp_data": {
    "event": "summary",
    "content": "..."
  }
}
```

而 A2A 返回的是 JSON-RPC SSE：

```json
{
  "jsonrpc": "2.0",
  "result": {
    "artifactUpdate": {}
  }
}
```

两者格式不兼容。

#### 解决方法

在 `stream-debug-ui/server.js` 代理层增加 A2A SSE 转换：

| A2A 原生内容 | 转换后 UI 事件 |
|-------------|----------------|
| `artifactUpdate.artifact.parts[].text` | `summary` |
| `TASK_STATE_SUBMITTED` | `conversation_start` |
| `TASK_STATE_COMPLETED` | `conversation_end` |
| JSON-RPC error | `stream_error` |
| failed/canceled/rejected 状态 | `stream_error` |

转换后返回前端：

```json
{
  "success": true,
  "custom_rsp_data": {
    "event": "summary",
    "content": "..."
  }
}
```

#### 验证结果

用户确认：

```text
前端已经收到
```

说明前端展示链路已打通。

### Q12：方案中的工具注册 API 与 SDK 实际不一致

#### 现象

P17 原计划按 `agent.registerTool()` 注册业务工具。

#### 根因

当前 OpenJiuwen DeepAgent SDK 实际 API 是：

```java
DeepAgent.registerHarnessTool(Tool tool)
```

而 Rail 注册 API 是：

```java
agent.getAgent().registerRail(rail)
```

#### 解决方法

P17 实现使用实际 API：

```java
agent.registerHarnessTool(tool);
```

并更新文档说明该 API 差异。

#### 验证结果

P17 测试验证工具进入 DeepAgent 能力列表。

## 4. 已形成的关键经验

### 4.1 A2A SSE 请求必须显式声明 Accept

A2A 流式请求必须带：

```http
Accept: text/event-stream
```

否则可能命中非 SSE handler，导致响应序列化异常。

---

### 4.2 stream-debug-ui 不能直接展示 A2A 原生 JSON-RPC SSE

`stream-debug-ui` 的 UI 渲染协议与 A2A JSON-RPC SSE 不同，需要代理层转换。

当前转换已满足基础展示，但复杂事件仍需扩展。

---

### 4.3 DeepAgent 是包装对象，不直接等同 BaseAgent

当前适配方式是：

```java
return deepAgent.getAgent();
```

用于满足 `OpenJiuwenAgentRuntimeHandler#createOpenJiuwenAgent` 返回 `BaseAgent` 的契约。

---

### 4.4 工具注册与 Rail 注册 API 不同

当前 SDK 实际 API：

```java
agent.registerHarnessTool(tool);
agent.getAgent().registerRail(rail);
```

后续文档和实现应避免继续使用方案中的假设 API `registerTool()`。

---

### 4.5 P17 已打通基础注册，不代表业务工具执行闭环完成

P17 当前完成的是：

```text
构建工具 → 注册工具 → 能力列表可见 → 可直接调用
```

但以下仍属于后续穿刺：

- `lite_todo_write` 的真实 Todo 状态更新事件
- `call_mcp` 的真实沙箱执行
- `call_versatile` 的真实委托调用
- `ask_user` 的真实 A2A INPUT_REQUIRED / resume
- `cancel_task` 的真实任务取消传播
