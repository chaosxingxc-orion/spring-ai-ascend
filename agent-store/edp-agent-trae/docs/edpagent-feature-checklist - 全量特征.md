# EDPAgent 特性清单

> 从业务功能视角描述 EDPAgent（Enterprise Dynamic Planning Agent）的全部能力特性。

|------|------|
| 生成时间 | 2026-05-27 09:16:19 |
| 文档版本 | v1.0 |
| 适用版本 | EDPAgent v1.x |

## 一、产品定位

| # | 特性 | 说明 |
|---|------|------|
| 1.1 | 规则驱动的企业级智能客服 | 通过业务规则配置文件定义智能体的行为边界与业务流程，无需修改代码即可适配不同业务场景 |
| 1.2 | 确定性业务流程编排 | 以固定步骤、有限状态、强合规的方式编排金融业务流程（推荐→选品→购买→资金筹划），确保每步都符合业务规范 |
| 1.3 | 实时交互式对话体验 | 将对话过程拆解为思考、规划、执行、确认、总结等多个阶段，通过事件流实时推送到前端，用户可感知每一步进展 |

## 二、运行架构

### 2.1 服务化部署

| # | 特性 | 说明 |
|---|------|------|
| 2.1.1 | 容器化独立服务 | 以 Docker 镜像形式交付，包含智能体运行时与业务逻辑，一键启动即可对外服务 |
| 2.1.2 | 面向企业的网关适配 | 支持企业统一 API 网关认证（Token/用户ID/自定义请求头），无缝接入银行/保险内部系统 |
| 2.1.3 | 流式响应接口 | 以异步事件流形式返回对话结果，前端可实时渲染思考动画、进度条、确认卡片等交互组件 |

### 2.2 协作与委派

| # | 特性 | 说明 |
|---|------|------|
| 2.2.1 | 统一智能体 + 拦截分流 | 单一智能体处理所有业务，通过拦截机制将不同类型的工具调用分流到对应的执行路径，无需多智能体协调 |
| 2.2.2 | 外部工作流委派 | 当需要执行银行转账、购买理财等真实业务操作时，将任务委派给外部编排器执行，智能体本身不直接调用银行接口 |
| 2.2.3 | 业务技能按需加载 | 智能体按需读取业务技能文档，了解当前步骤可用的脚本命令与参数，避免一次性注入过多信息 |
| 2.2.4 | A2A跨进程智能体调用 🚀 | 支持通过A2A协议调用其他智能体，各智能体运行在独立进程中，实现进程级故障隔离，单个智能体异常不会影响其他智能体运行 |
| 2.2.5 | 主/子Agent异步执行 🚀 | 支持主智能体与子智能体异步并行执行，主智能体委派任务后无需阻塞等待，可同时处理其他子任务或工作流调用 |
| 2.2.6 | 工作流与Agent异步并行 🚀 | 支持Versatile工作流调用与智能体调用异步并行执行，多路任务同时运行，提升端到端响应速度 |

### 2.3 会话持久化

| # | 特性 | 说明 |
|---|------|------|
| 2.3.1 | 跨请求会话保持 | 使用 Redis 持久化对话状态，用户关闭页面后重新进入可恢复上次对话进度 |
| 2.3.2 | 中断后断点续行 | 工作流执行期间智能体暂停等待结果，用户下次进入时自动从断点恢复，无需重新开始 |
| 2.3.3 | 任务取消后全量清理 | 用户取消操作后，彻底清除 Redis、内存、上下文三层状态，防止旧数据污染新对话 |

### 2.4 大模型接入

| # | 特性 | 说明 |
|---|------|------|
| 2.4.1 | 企业模型服务对接 | 支持通过企业统一模型网关接入国产大模型（智谱GLM、DeepSeek、通义千问等） |
| 2.4.2 | 自定义认证头注入 | 可配置 Token、用户ID、额外请求头，适配不同企业的 API 网关认证体系 |
| 2.4.3 | 空响应自动防护 | 针对推理模型偶发的"只思考不回答"问题，自动调整采样参数确保稳定输出 |
| 2.4.4 | 敏感配置加密存储 | API Key、数据库密码等敏感配置支持加密存储，运行时自动解密，避免明文泄露 |

## 三、规则与约束

### 3.1 六规则业务管控

| # | 特性 | 说明 |
|---|------|------|
| 3.1.1 | 业务范围管控 | 配置允许的业务类型列表，用户提出超范围需求时自动拒绝并提示引导话术 |
| 3.1.2 | 规划步骤模板 | 预定义5步规划流程（需求解析→目标拆解→方案生成→规则校验→结果输出），规范智能体的思考路径 |
| 3.1.3 | 任务依赖声明 | 声明业务步骤之间的前后依赖关系，确保流程按正确顺序执行 |
| 3.1.4 | 全局交互次数上限 | 限制智能体单次对话的最大工具调用次数（默认100次），防止无限循环消耗资源 |
| 3.1.5 | 单工具调用次数上限 | 按工具名设置独立调用上限（如转账最多3次），防止单一操作被反复触发 |
| 3.1.6 | 总结格式规范 | 约束最终回答的格式、最大长度、必含字段，确保输出符合业务规范 |
| 3.1.7 | 业务步骤强约束 | 预定义业务步骤目录，智能体只能选择已有步骤，不能自创步骤，确保流程合规 |
| 3.1.8 | 规则热更新 | 所有业务规则写在配置文件中，修改配置即可调整行为，无需重新部署 |

### 3.2 拦截与管控机制

| # | 特性 | 说明 |
|---|------|------|
| 3.2.1 | 全局次数熔断 | 工具调用次数达到全局上限时自动终止对话，返回已完成的进度 |
| 3.2.2 | 单工具次数熔断 | 单个工具调用次数达到上限时自动终止，并向用户说明原因 |
| 3.2.3 | 话术中斤断言 | 智能体需要向用户提问时，先匹配话术模板再中断，确保用户看到的是标准话术而非原始文本 |
| 3.2.4 | 工作流委派拦截 | 需要调用外部工作流时自动拦截并委派，等外部系统返回结果后恢复执行 |
| 3.2.5 | 数据获取拦截 | 需要获取产品推荐数据时自动拦截，在隔离环境中执行脚本获取数据 |
| 3.2.6 | 任务取消拦截 | 用户取消时立即终止对话流程，注入取消话术，标记待清理的会话状态 |
| 3.2.7 | 全链路调用日志 | 记录每次大模型调用与工具调用的输入、输出、耗时，用于问题排查与行为审计 |
| 3.2.8 | 拦截优先级控制 | 不同拦截机制按优先级顺序执行，确保高优先级操作（如取消）优先于低优先级操作 |

### 3.3 话术管理系统

| # | 特性 | 说明 |
|---|------|------|
| 3.3.1 | 话术模板库 | 内置20+条业务话术模板（推荐成功/失败、购买确认、转账提示、超时提醒等），统一客服表达风格 |
| 3.3.2 | 话术动态匹配 | 根据业务执行结果（成功/失败）自动匹配对应话术，无需硬编码判断逻辑 |
| 3.3.3 | 话术变量安全替换 | 话术模板中的变量（如产品名、金额）缺失时自动替换为空串，不会因缺少数据导致话术显示异常 |
| 3.3.4 | 话术变量智能注入 | 智能体在调用工具时传入业务变量（如产品名称、收益率），话术系统自动填充模板 |
| 3.3.5 | 大模型输出容错 | 智能体偶尔输出格式不规范的参数（中文引号、多余空格等），话术系统自动修正解析 |
| 3.3.6 | 推荐结果话术 | 产品推荐成功时展示产品列表话术，无匹配产品时展示空结果引导话术 |
| 3.3.7 | 购买确认话术 | 购买理财产品前展示产品详情确认话术，包含产品名称、金额、收益率等关键信息 |
| 3.3.8 | 异常场景话术 | 覆盖任务取消、会话超时、购买中断等异常场景的标准话术，避免裸异常信息暴露给用户 |
| 3.3.9 | 非中断进度提示 | 在不中断对话的情况下，向用户发送操作进度提示（如"正在查询余额..."），提升等待体验 |
| 3.3.10 | 空结果友好提示 | 产品查询无结果时展示友好引导话术，而非沉默无响应 |

## 四、任务规划与进度管理

| # | 特性 | 说明 |
|---|------|------|
| 4.1 | 规则驱动任务规划 | 根据业务规则预定义的规划模板自动拆解用户需求为可执行步骤 |
| 4.2 | 步骤枚举强约束 | 智能体只能从预定义的业务步骤中选择，不能自创步骤，确保任务流程符合业务规范 |
| 4.3 | 待办清单实时更新 | 每完成一步即刻更新待办清单状态，用户可随时查看当前进度 |
| 4.4 | 进度事件实时推送 | 任务开始、执行中、完成等状态变化实时推送到前端，支持进度条等UI组件渲染 |
| 4.5 | 进度跨请求保持 | 待办清单存储在 Redis 中，用户中途离开再回来时进度不丢失 |
| 4.6 | 任务完成自动清理 | 所有步骤完成后自动清空待办清单，避免已完成任务残留 |
| 4.7 | 步骤与业务技能绑定 | 每个业务步骤关联一个业务技能包，选择步骤即声明使用对应技能，确保技能调用不遗漏 |

## 五、隔离执行环境

### 5.1 运行模式

| # | 特性 | 说明 |
|---|------|------|
| 5.1.1 | 开发/生产双模式 | 开发环境使用本机直接执行，生产环境使用远程沙箱隔离执行，通过配置一键切换 |
| 5.1.2 | 远程沙箱隔离执行 | 业务脚本在远程隔离容器中执行，与智能体运行环境物理隔离，防止脚本影响主服务 |
| 5.1.3 | 本地直接执行 | 开发调试阶段可直接在本机执行脚本，无需搭建沙箱环境 |
| 5.1.4 | 沙箱自动创建 | 服务启动时自动创建沙箱容器实例，无需手动管理容器生命周期 |
| 5.1.5 | 多实例隔离 | 每个智能体实例绑定独立的沙箱容器，多实例并存时互不干扰 |

### 5.2 业务技能包管理

| # | 特性 | 说明 |
|---|------|------|
| 5.2.1 | 技能包自动打包 | 服务启动时自动将业务技能目录打包为压缩包 |
| 5.2.2 | 技能包自动上传 | 沙箱模式下自动将技能包上传到远程容器 |
| 5.2.3 | 技能包自动解压 | 上传后在容器内自动解压到指定目录 |
| 5.2.4 | 解压目录可配置 | 通过环境变量配置技能包解压目标路径，适配不同容器环境 |
| 5.2.5 | 技能文档按需查阅 | 智能体按需读取技能文档，了解可用脚本与参数说明，避免信息过载 |

### 5.3 脚本执行控制

| # | 特性 | 说明 |
|---|------|------|
| 5.3.1 | 统一脚本调用接口 | 所有业务脚本通过统一接口调用，不区分本地/沙箱模式 |
| 5.3.2 | 工作目录自动切换 | 脚本执行前自动切换到技能目录，脚本内使用相对路径即可 |
| 5.3.3 | 业务参数环境变量注入 | 业务参数、认证信息等通过环境变量注入到脚本进程，脚本无需额外读取配置 |
| 5.3.4 | 执行超时保护 | 脚本执行默认60秒超时，防止异常脚本无限挂起占用资源 |
| 5.3.5 | 多路结果解析 | 标准输出解析为业务数据，标准错误记录为日志，退出码判断执行状态 |
| 5.3.6 | 空结果友好处理 | 脚本无输出时自动触发空结果提示话术，而非让用户面对空白页面 |

### 5.4 脚本输入数据安全构造

| # | 特性 | 说明 |
|---|------|------|
| 5.4.1 | 业务参数自动传递 | 智能体生成的业务参数自动注入到脚本输入中 |
| 5.4.2 | 认证信息自动注入 | 用户身份、Token等认证信息从会话上下文自动注入，不经过大模型，防止泄露 |
| 5.4.3 | 敏感配置安全传递 | 敏感配置（API地址、密钥等）大模型只传递变量名，实际值由系统从安全存储读取后注入 |
| 5.4.4 | 默认敏感配置兜底 | 大模型未传递敏感变量名时，自动注入默认的安全配置列表，确保脚本可用 |
| 5.4.5 | 跨轮次查询上下文保持 | 分页查询等场景下，上次查询条件自动注入到本次脚本输入，保持查询连续性 |
| 5.4.6 | 输入数据统一序列化 | 所有输入参数统一序列化为JSON字符串传递，脚本解析方式一致 |

### 5.5 多源数据归一化

| # | 特性 | 说明 |
|---|------|------|
| 5.5.1 | 归一化脚本按需配置 | 每个业务工具可配置专属的归一化脚本，将不同数据源的结构统一为标准格式 |
| 5.5.2 | 多源数据合并 | 归一化脚本将产品推荐数据与银行系统返回数据合并，生成统一视图供智能体使用 |
| 5.5.3 | 执行结果状态判定 | 归一化脚本输出包含成功/失败状态，系统据此自动选择对应的用户话术 |
| 5.5.4 | 进度提示动态注入 | 归一化脚本可在结果中注入进度提示信息，系统自动推送到前端 |
| 5.5.5 | 进度提示与话术互斥 | 有进度提示时不再展示标准话术，避免同时出现两条提示造成信息冗余 |
| 5.5.6 | 无脚本数据透传 | 未配置归一化脚本时，原始数据直接传递给智能体，不影响业务流程 |
| 5.5.7 | 内部字段自动清理 | 归一化结果中的内部字段（进度提示等）在传递给大模型前自动清除，防止干扰推理 |

### 5.6 异常容错

| # | 特性 | 说明 |
|---|------|------|
| 5.6.1 | 脚本异常统一兜底 | 脚本执行失败时返回统一格式的空结果，智能体据此引导用户重试 |
| 5.6.2 | 无输出自动检测 | 脚本无输出时自动识别并触发空结果提示话术 |
| 5.6.3 | 输出格式异常降级 | 归一化脚本输出格式异常时，直接使用原始数据，保证业务流程不中断 |
| 5.6.4 | 沙箱不可用时降级 | 沙箱环境不可用时跳过脚本执行，直接返回原始数据 |
| 5.6.5 | 错误上下文自动重置 | 脚本执行失败时自动清除上次查询条件，防止下次查询继承错误状态 |

## 六、Versatile 工作流调用

### 6.1 通用工作流调用

| # | 特性 | 说明 |
|---|------|------|
| 6.1.1 | 统一业务操作入口 | 余额查询、转账、理财购买等所有业务操作通过同一个工具调用，按意图参数差异化路由 |
| 6.1.2 | 自然语言任务描述 | 智能体用自然语言描述要执行的任务（如"查询尾号6605的卡余额"），传给工作流引擎执行 |
| 6.1.3 | 业务意图分类 | 标识当前操作类型（查询余额/转账/购买/推荐），工作流引擎据此路由到对应业务流程 |
| 6.1.4 | 结果处理脚本配置 | 每次调用可指定归一化脚本，将工作流返回的原始数据转为智能体可理解的结构 |
| 6.1.5 | 结果话术预声明 | 调用时声明成功/失败两种话术，执行完成后自动匹配并展示给用户 |
| 6.1.6 | 进度提示上下文 | 为非中断场景传递进度提示所需的上下文信息（如购买金额、产品类型） |
| 6.1.7 | 任务描述智能补全 | 当智能体未提供任务描述时，自动使用上一步推荐查询的缓存描述，减少重复输入 |
| 6.1.8 | 一级控制器调度工作流 | 通过一级控制器（Orchestrator）调度Versatile工作流，由编排器统一管理任务分发、依赖关系与结果回收 |
| 6.1.9 | 直接调用工作流 🚀 | 支持智能体跳过一级控制器，直接调用Versatile工作流执行业务操作，减少中间环节，降低延迟 |

### 6.2 委托与中断恢复

| # | 特性 | 说明 |
|---|------|------|
| 6.2.1 | 业务操作暂停等待 | 需要执行真实业务操作（转账/购买）时，智能体暂停并通知外部系统执行 |
| 6.2.2 | 委托信息记录 | 暂停时记录操作意图与任务描述，等待外部系统处理完毕后继续 |
| 6.2.3 | 委托请求推送 | 将委托信息推送给外部编排器，编排器据此调用对应的银行工作流 |
| 6.2.4 | 外部系统执行 | 外部编排器调用银行系统工作流（如VersatileAdapter），完成真实业务操作 |
| 6.2.5 | 执行结果恢复 | 外部系统返回结果后，用户下次进入对话时智能体自动恢复执行，处理结果并回复用户 |
| 6.2.6 | 委托信息兜底恢复 | 框架状态回滚导致委托信息丢失时，自动从备用存储重建，确保操作不丢失 |
| 6.2.7 | 无外部依赖设计 | 委托逻辑不依赖特定通信框架，可对接任意编排器实现 |

### 6.3 请求格式适配

| # | 特性 | 说明 |
|---|------|------|
| 6.3.1 | 任务描述自动注入 | 将智能体生成的任务描述注入到工作流请求体中，工作流引擎据此执行 |
| 6.3.2 | 用户输入提取 | 从工作流格式的请求体中提取用户原始输入，用于上下文理解 |
| 6.3.3 | 原始请求保留 | 首轮请求的完整数据保存在会话中，后续步骤可读取用户身份等认证信息 |
| 6.3.4 | 请求隔离 | 请求适配时不修改原始数据，确保数据完整性 |

### 6.4 续轮数据处理

| # | 特性 | 说明 |
|---|------|------|
| 6.4.1 | 工作流结果自动提取 | 从工作流返回数据中自动提取核心业务数据，兼容多种返回格式 |
