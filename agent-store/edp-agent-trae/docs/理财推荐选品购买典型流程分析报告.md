# 理财推荐选品购买典型流程分析报告

## 1. 报告目的

本报告基于重启智能体后，浏览器端完成的三轮“帮我推荐几款稳健型理财产品”完整测试日志，分析 EDPAgent 在理财推荐、选品、确认、资金筹划、资金汇聚、购买成功与资金不足终止链路中的端到端执行过程。

报告重点覆盖：

- 从 Query `帮我推荐几款稳健型理财产品` 开始的请求接收过程。
- A2A `SendStreamingMessage` 流式事件输出。
- ReAct 处理过程：规划、工具执行、观察、反思。
- `skill_tool`、`call_versatile`、`ask_user`、`lite_todo_write` 的协作过程。
- 三类典型购买路径：
  - 余额充足：直接购买。
  - 余额不足但两卡合计充足：查询默认储蓄卡、资金汇聚后购买。
  - 余额不足且两卡合计不足：查询余额后终止购买。
- `readFile` 告警在统一 `skill_tool` 后的现状。

### 6.3 推荐阶段 ReAct 处理

第二轮推荐阶段执行链路如下：

1. `ReAct stream iteration 1/100`：识别推荐需求。
2. 调用 `skill_tool(product_recommend_skill)` 加载推荐 Skill。
3. 曾尝试 `skill_tool(product_recommend_skill, relative_file_path="scripts")`，该调用返回失败，因为 `scripts` 是目录而非具体文件；随后模型继续按主 Skill 指引执行。
4. 调用 `call_mcp` 获取 MCP 推荐数据意图。
5. 调用 `call_versatile` 执行低码理财推荐。
6. 观察返回的产品列表与理财卡尾号。
7. 反思并输出推荐列表。

该阶段虽然出现一次非关键的 `skill_tool` 目录读取失败，但推荐业务最终完成，不影响后续流程。

因此当前状态是：

| 实际 ability_manager | `skill_tool` / `list_skill` | 可用 |
| 业务主流程 | 使用 `skill_tool` | 三轮均成功加载 Skill 并完成对应终态 |

### 10.3 影响评估

- 第三轮正确识别两卡合计不足并终止购买。

但该告警仍需后续跟踪：

