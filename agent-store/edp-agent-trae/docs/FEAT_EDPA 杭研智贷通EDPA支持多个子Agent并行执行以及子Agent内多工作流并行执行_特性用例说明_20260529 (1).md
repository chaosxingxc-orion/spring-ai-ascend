## 1. 特性概述

- **特性描述**：本特性使高码动态规划智能体（EDPA）具备将单个用户查询自动拆解为多个互相无依赖的子Agent并行调度执行的能力。每个子Agent对应一个独立的业务实体（如企业/组织/账户等），子Agent内部支持串行编排多个低码工作流（如先判定再执行），而不同子Agent之间完全隔离、自动并行，无需用户逐一手动创建多Agent一级控制器。同时，Skill引擎层支持并行调用多个低码工作流，并通过全局并发控制保护后端稳定性。系统为主任务和每个子Agent独立维护ToDo List、会话上下文、状态机、执行轨迹日志，并按主任务和子Agent维度独立输出与存储结果。

核心能力包括：
  - 自动任务拆解：单个用户 Query 自动拆分为多个独立子Agent，每个子Agent对应一个目标对象；
  - 多子 Agent 之间并行执行：不同目标对象的子Agent之间无依赖时自动并行调度；
  - 子 Agent 内多工作流并行：同一Agent内的多个工作流按规则支持并行执行；
  - 方案泛化性：EDPA既支持多个相同子Agent并行调用，也支持多个不同子Agent的并行调用。
  - Agent运行时隔离：每个Agent拥有独立的上下文、状态机、ToDo List 与执行轨迹日志，单任务失败不影响其他任务；
  
  能力范围（先支持模式二，后续考虑规划支持模式一）：
  - 模式一：主/子Agent异步执行，多子Agent之间并行执行。架构差异：主任务非阻塞（创建子Agent后立即返回）；子Agent结果通过A2A协议异步回调；需状态持久化支持断线重连；A2A协议需支持SendStreamingMessage长连接保持。
  - 模式二：主/子Agent同步执行，多子Agent之间并行执行。架构差异：主任务阻塞等待子Agent完成；编排层实时转发执行轨迹；无需状态持久化；标准A2A请求-响应模式即可满足。
  
    
  **业务价值**：
  
  - **终端业务用户**：一条指令即可批量发起多主体任务，系统自动拆分并行处理，无需手动编排多控制器；各任务执行互不干扰、结果独立输出，支持单个任务暂停 / 恢复 / 终止，大幅降低操作成本、提升任务处理效率。
  - **平台开发者 / 配置管理员**：无需手动搭建多Agent一级控制器，通过统一的Agent Rule文件即可声明主任务拆解规则与子Agent业务规则；直接复用已有低码工作流（不经过一级控制器），Skill底层能力无需修改，仅通过Adaptor层配置即可适配不同接入模式，大幅提升编排扩展性与易用性。
  - **平台运维 / 合规管理人员**：支持全局及按工作流类型自定义并发限流，保护后端引擎稳定性；每个任务独立留存规划、调用、交互全链路日志，支持按业务主体维度检索追溯，满足通用合规审计要求；单任务异常 / 失败不影响整体链路，系统容错与健壮性显著提升。

## 2. 核心参与者与触发条件

- **参与角色**：业务用户、高码动态规划智能体 EDPA 、低码工作流引擎、Skill 、平台配置管理员、运维管理员、前端交互层。
- **触发条件**：
  - 用户query触发：用户输入一条包含多个实体标识的自然语言指令，指令中隐含需对各实体分别执行独立业务流程的意图（如"请对A、B、C分别执行流程X，满足条件则生成报告"）。
- **约束条件**：
  - 不支持子Agent内的工作流中断：同一子Agent内的多个工作流不支持中途取消/暂停。
  - 同一子Agent内，同一个低码工作流不能被并行调用。

### 2.1 状态机枚举定义

**主任务状态枚举**：

| 状态 | 名称 | 说明 |
|------|------|------|
| `pending` | 待执行 | 主任务已创建，等待子Agent启动 |
| `running` | 运行中 | 主任务正在执行，子Agent并行运行 |
| `completed` | 已完成 | 所有子Agent成功完成 |
| `completed_with_partial_failures` | 部分成功 | 部分子Agent失败，其余成功完成 |
| `failed` | 失败 | 主任务执行失败 |
| `cancelled` | 已取消 | 用户主动取消任务 |
| `timeout` | 超时 | 任务执行超时 |

**子Agent状态枚举**：

| 状态 | 名称 | 说明 |
|------|------|------|
| `pending` | 待执行 | 子Agent已创建，等待启动 |
| `running` | 运行中 | 子Agent正在执行工作流 |
| `completed` | 已完成 | 子Agent成功完成所有工作流 |
| `failed` | 失败 | 子Agent执行失败 |
| `cancelled` | 已取消 | 用户主动取消或全局中断 |
| `timeout` | 超时 | 任务执行超时 |

**状态流转说明**：
- 主任务：`pending` → `running` → `completed` / `completed_with_partial_failures` / `failed` / `cancelled` / `timeout`
- 子Agent：`pending` → `running` → `completed` / `failed` / `cancelled` / `timeout`

## 3. 标准流程用例

### 用例 3.1：[单 Query 触发多个子Agent并行任务自动拆解与执行]

> **本用例基于模式二：主/子Agent同步执行，多子Agent之间并行执行**

- **前置条件**：

  - 已配置Agent Rule文件，描述主任务拆解规则与子Agent业务规则（主任务和子Agent分开配置Agent Rule文件）；
  - 已创建并发布所需的低码工作流，工作流已配置Intent字段与工作流的唯一映射关系；
  - 全局并发上限已配置（如最大同时运行3个子Agent）；
  - 本次查询涉及3个实体（A、B、C），未超过并发上限；
  - 实体识别校验：已配置业务实体库，EDPA识别实体后需与实体库匹配校验，未匹配实体将跳过并记录日志；
  - 数量一致性校验：识别出的实体数量应与Query中标识的实体数量一致，若不一致需记录异常日志。

- **输入参数**：用户自然语言指令：请对对象 A、对象 B、对象 C 进行流程判定，若判定结果为指定类型，则触发专业内容生成流程输出标准文档，并将文档推送至本人。

- **执行步骤**：

  1. 终端用户提交包含多个实体的Query。
  2. EDPA接收Query，通过LLM+Agent Rule理解意图，识别出需对A、B、C三个实体分别执行独立业务流程。
  3. EDPA将识别出的实体与业务实体库进行匹配校验，确认A、B、C均为有效实体；校验识别数量（3）与Query标识数量（3）一致。
  4. EDPA自动将主任务拆解为3个并行子Agent（子Agent-A、子Agent-B、子Agent-C），每个子Agent绑定一个实体ID。
  5. EDPA根据全局并发上限（3）判断3个子Agent可全部并行启动，为各子Agent创建独立的ToDo List、会话上下文、状态机（初始状态：运行中）。
  6. 子Agent-A、子Agent-B、子Agent-C并行执行，互不干扰。编排层实时转发子Agent执行轨迹至前端；主任务阻塞等待所有子Agent完成。
  7. 主任务恢复执行，聚合各子Agent结果，继续规划后续流程。
  8. 前端界面展示执行轨迹，包括子Agent执行轨迹和主任务执行轨迹。

- **预期输出/结果**：

  - 多主体子Agent实现并行执行，整体耗时 ≤ 1.3 × max(T_A, T_B, T_C)（并行调度开销不超过最长子任务耗时的30%）；
  - 每个实体的报告独立生成、独立存储，通过结果URL可分别访问；响应按子AgentID分别返回；
  - 展示三组并行进度状态，支持逐实体查看详细执行轨迹日志；
  - 各子Agent上下文、状态、日志、结果完全隔离存储，无参数串扰、流程耦合问题。

### 用例 3.2：[Skill并行调用多个低码工作流]

- **前置条件**：业务 Skill 已完成多低码工作流编排配置；Skill 适配层完成两种接入模式适配对接，Adaptor层已配置Intent字段到工作流的标准映射规则；待调用多个低码工作流无执行先后依赖；待并行调度的多个工作流实例之间无冲突（同一工作流不在同一Agent内被重复并行调用）；

- **输入参数**：EDPA在子Agent执行过程中触发某Skill，该Skill需同时调用3个工作流、多工作流 Intent 标识集合、通用业务入参。

- **执行步骤**：
  1. EDPA在子Agent（如子Agent-A）执行过程中触发Skill。
  2. Skill识别出需并行调用工作流W_a、W_b、W_c。
  3. Skill通过Adaptor层，根据Intent字段分别映射到W_a、W_b、W_c的工作流实例。
  4. 三个工作流并行提交至低码工作流引擎执行。
  5. 各工作流独立执行并流式返回报告内容，编排层按子AgentID分流转发至前端。
  6. 当所有工作流执行完成后，Skill调用报告内容汇聚工作流（如前置条件已配置），形成尽调报告，输出OBS地址（报告文件的URL地址）。
  7. 各工作流独立返回执行的结果（含执行状态，耗时，结果URL等），Skill引擎聚合后返回给EDPA。
  8. Agent继续后续流程或标记完成。

- **预期输出/结果**：
  - Skill内多个工作流并行执行，无需串行等待，子Agent整体执行效率提升；
  - 底层Skill能力无需修改，仅通过Adaptor配置即可适配"一级控制器直连"或"工作流编排"两种接入模式；
  - 工作流ID与子AgentID动态绑定，响应结果按子AgentID分别返回。

### 用例 3.3：[并行任务全流程过程可视 + 单主体独立执行轨迹呈现]

- **前置条件**：多主体子Agent已进入并行执行状态；前端运维页面具备任务分组渲染、进度展示、日志查看基础能力。

- **输入参数**：主任务唯一 ID、各子Agent ID、业务主体唯一标识。

- **执行步骤**：
  1. **主任务进度展示**：展示主任务的整体状态（`运行中` / `已完成` / `部分成功` / `失败` / `已取消` / `超时`）。
  2. **子Agent进度独立刷新**：各子Agent执行轨迹独立刷新，互不干扰。
  3. **执行轨迹呈现**：EDPA呈现执行轨迹内容包含：意图解析步骤、分类工作流调用记录、条件判断结果、后续处理工作流调用记录，各子Agent状态。后端输出执行轨迹事件流，不输出原始Chain-of-Thought。

- **预期输出/结果**：并行任务分组和执行状态呈现。

## 4. 异常与扩展流程用例

### 用例 4.1：[用户主动全局中断全量任务]

- **前置条件**：多实体并行任务处于执行运行状态，多个子任务同步运行中（如3个子任务均在运行）。

- **输入参数**：用户操作：点击"取消全部任务"按钮。

- **执行步骤**：
  1. 用户下发全局任务中断指令，直接终止本次整体业务查询流程。
  2. EDPA 统一向所有正在运行的子 Agent 下发中断终止信号（前端视角取消，后台best-effort停止）。
  3. 系统统一回传内容：已完成子任务有效结果 + 本次被强制中断的子任务明细清单。
  4. 本次任务中断后直接终止当前整轮业务流程；用户再次发起触发，即为全新独立查询流程，不再接续旧任务。

- **预期输出/结果**：
  - 数据留存：已办结实体任务结果永久保留，无数据丢失。
  - 流程隔离：中断即放弃本轮全部业务流程，重启触发为全新独立任务。
  - 后台说明：已提交至低码引擎的工作流实例可能继续运行至自然完成（best-effort停止语义）。

### 用例 4.2：[并发超限提醒]

- **前置条件**：全局并发上限配置为3，用户一次query查询包含8个实体（子Agent）。

- **输入参数**：Query实体数-8个。全局并发上限 -3个。

- **执行步骤**：
  1. EDPA识别Query包含8个实体，需拆解为8个子Agent。
  2. EDPA判断 8 > 全局并发上限3，触发超限保护逻辑。
  3. 产品决策：自动取前3个实体执行+提示剩余实体。系统返回提示："已自动选择前3个实体执行，剩余5个实体可通过分批查询处理。"
  4. 用户可调整Query实体数量，重新提交处理剩余实体。

- **预期输出/结果**：
  - 系统保护：后端工作流引擎不被压垮，不触发限流。
  - 用户引导：用户获得明确的超限提示与分批建议。
  - 兼容历史：并发控制逻辑兼容之前版本与接口，对已有单实体任务无影响。

### 用例 4.3：[单条子 Agent 执行异常故障隔离]

- **前置条件**：多个子 Agent 已处于并行正常运行状态；其中单一子 Agent 出现接口报错、资源不足、逻辑异常等运行故障。

- **输入参数**：故障子任务 ID、异常状态识别指令。

- **执行步骤**：
  1. 系统监测到某一个子 Agent 出现运行异常、执行失败（故障检测延迟<5秒，其余子Agent延迟增量<5%）。
  2. 仅对故障子 Agent 进行状态标记、终止运行，留存完整异常日志。
  3. 其余所有并行运行的正常子 Agent 不受任何影响，持续按流程执行。
  4. 主任务保持运行状态，等待正常子 Agent 全部执行完成。
  5. 子Agent全部执行完成后，主任务状态切换为已完成或部分成功。

- **预期输出/结果**：
  - 实现故障强隔离，单点子 Agent 异常不会造成全链路任务卡顿、失败。
  - 异常日志独立归档，可通过主体 ID 快速检索排查问题。
  - 业务整体流程不受局部故障影响，保障批量业务整体推进。
  - 量化标准：故障子Agent在异常后≤10秒内标记为failed状态。

## 5. 依赖项

- **依赖说明**：
  1. 低码工作流引擎：需支持：①工作流实例ID与子AgentID动态绑定；②多工作流并发执行；③执行结果返回URL；④兼容历史并发接口。
  2. Skill ：需支持：①并行调用多个低码工作流；②通过Intent字段映射工作流；③聚合多工作流返回结果。
  3. 状态机服务：需支持：①多子Agent独立状态机（运行/挂起/完成/失败）；②独立会话上下文隔离；③执行轨迹日志独立存储；④按实体维度检索。
  4. Adaptor适配层：需支持：①Intent字段到工作流的标准映射配置；②适配"一级控制器直连"与"工作流编排"两种接入模式。
  5. Agent Rule配置：需支持：①主任务拆解规则；②子Agent业务规则；③主任务与子Agent分开配置Rule文件。
  6. 全局并发控制模块：需支持：①全局并发上限配置；②Query实体数识别与超限判断；③超限提醒返回；④兼容历史版本与接口。
  7. 前端交互层：需支持：①分组进度条展示；②按实体查看独立执行轨迹日志；③全局中断操作；④并发超限提示UI。
