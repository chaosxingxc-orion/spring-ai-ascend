# ADR-0163: forwarding-centric package layering + broker SPI extraction (supersedes ADR-0162)

- **Status:** Accepted
- **Date:** 2026-07-16
- **Change slug:** `forwarding-reorg`
- **Supersedes:** ADR-0162 (`agent-bus-layering`) — its top-level `eventbus.runtime` + `common` plane packages are folded INTO `forwarding`; its `gateway.runtime ↛ eventbus.runtime` rule is replaced by `gateway.runtime ↛ forwarding.runtime.relay` (narrower — see Decision 4).
- **Related:** `docs/4plus1/delta/forwarding-reorg/`; ADR-0160 (web confined to `gateway.runtime`); ADR-0162 (the prior layering, superseded); the broker-filtering decision packet (§3 D3/D4/D5/D8).

## Context

ADR-0162 (the just-closed `agent-bus-layering` slice) established top-level `eventbus.runtime` + `common` plane packages + a `gateway.runtime ↛ eventbus.runtime` ArchUnit rule. On review, that layering left the `forwarding/` substrate as the reorg's natural anchor under-used: the event-bus wiring + the shared config sat as top-level planes rather than forwarding-internal. The user directed a **forwarding-centric** reorganization (`forwarding-reorg`) that (a) folds the event-bus wiring into `forwarding`, (b) moves `common`→`forwarding/common`, (c) extracts the broker SPI to `forwarding/spi/broker`, (d) splits the rocketmq impl into `broker/rocketmq`, and (e) frames the structure for building separate packages (event-bus process / producer-consumer SDK / gateway process). G4 sign-off (2026-07-16, "确认,5 分支全按方案") ratified the plan; G5 implemented it (sub-agent, BUILD SUCCESS 443 green/14 skip); G6 as-built confirmed the plan landed + surfaced a rule-scope drift (user-accepted).

## Decision

1. **`forwarding/common`** — `AgentBusBrokerProperties` (`@ConfigurationProperties("agent-bus")`, shared by both planes) lives in a NEW `com.huawei.ascend.bus.forwarding.common` package. Top-level `common/` is eliminated. The shared config is forwarding-internal.
2. **`forwarding/spi/broker`** — the broker SPI (5 classes, code-verified to reference only `forwarding.spi` types — no inversion) lives in a NEW `com.huawei.ascend.bus.forwarding.spi.broker` package: the 2 Port interfaces (`BrokerForwardingConsumerPort`/`BrokerForwardingRelayPort`) + the 3 value-object records they expose (`BrokerInboundMessage`/`BrokerProduceOutcome`/`DeliveryFilter`). Moved from `forwarding.runtime.transport.broker` (which keeps the 4 broker-common classes: `BrokerClientProperties`/`BrokerOutboundMessage`/`BrokerMessageHeaders`/`BrokerControlDescriptor`). The broker SPI is now visible at the SPI surface (callers of the Ports see these types), grouped under `forwarding/spi/` (not flat — a subpackage keeps the 5 broker SPI classes grouped vs the ~18 forwarding-domain SPI classes).
3. **`forwarding/runtime/relay`** — the 3 event-bus wiring files (`EventBusRelayConfiguration`/`EventBusRelaySchedulingConfig`/`RelayScheduler`) fold INTO `forwarding.runtime.relay`, co-located with `EventBusRelayWorker`/`RelayTick`/`RelayDispatchLoop` (the relay mechanism they wire). Top-level `eventbus.runtime/` is eliminated. `@Profile("eventbus")` + bean names unchanged.
4. **`forwarding/runtime/transport/broker/rocketmq`** — the 2 rocketmq impl (`RocketMqBrokerForwardingConsumer`/`Relay`) live in a NEW `com.huawei.ascend.bus.forwarding.runtime.transport.broker.rocketmq` subpackage (sibling dirs for future brokers — kafka/, nats/). Code-verified: they reference the broker SPI (Ports they implement + value objects) — NO broker-common types (favorable — fewer imports than the to-be anticipated).
5. **The plane boundary rule (NARROWER than ADR-0162's spirit — user-accepted drift).** ADR-0162's `gateway.runtime ↛ eventbus.runtime` is REPLACED by **`gateway.runtime.. ↛ forwarding.runtime.relay..`** — the gateway never reaches into the event-bus two-hop relay mechanism/wiring (now in `forwarding.runtime.relay`). The to-be plan's literal `gateway.runtime ↛ forwarding.runtime..` was **infeasible**: the gateway is a producer/consumer that legitimately wires `forwarding.runtime.{transport.broker, transport.broker.rocketmq, transport, persistence.jdbc}` (the broker adapters + jdbc outbox + transport resolvers + `BrokerControlDescriptor`). The realistic plane boundary is at the **relay package** (the gateway process form vs the event-bus relay process form), not the whole `forwarding.runtime`. A future stricter rule (`gateway ↛ forwarding.runtime` via a forwarding-runtime auto-config that provides the broker/jdbc beans, so the gateway depends only on `forwarding.spi` + `forwarding.common`) is flagged as a follow-on (out of scope for this reorg).
6. **Purity exemptions (the fold-in consequence).** Folding `EventBusRelayConfiguration` etc. + `AgentBusBrokerProperties` INTO `forwarding..` (from the exempt `eventbus.runtime`/`common` planes) brought legitimately-Spring/RocketMQ/`javax.sql`-using wiring under the `forwarding..` purity rules. `AgentBusForwardingSpiPurityTest` exempts `forwarding.runtime.relay` (Spring/`javax.sql`/RocketMQ) + `forwarding.common` (Spring) — mirroring the existing `persistence.jdbc`/`transport.broker` exemption pattern; `AgentBusForwardingRuntimeContractTest` + `AgentBusForwardingDesignContractTest` add `forwarding.spi.broker` to path-exclusions/sanctioned-homes (the broker SPI is pure Java; its javadoc names `org.apache.rocketmq` only to disclaim it).
7. **Build (Q1=b — UNCHANGED).** Single Maven module (`agent-bus`) + `spring-boot-maven-plugin repackage` + `@Profile` (gateway / eventbus+registry). The "build different packages" intent (event-bus process / SDK / gateway process) is delivered as a documented package-set boundary (Q4: SDK = `forwarding/{spi, spi/broker, common, runtime/{relay, transport.{a2a,broker}, persistence.jdbc}}`), NOT a Maven multi-module split — the `@Profile` mechanism already yields distinct process forms from one fat-jar. A Maven multi-module split is a deferred follow-on (the package reorg prepares for it).

## Consequences

- **New invariant (forwarding-centric layering):** `forwarding` is the reorg anchor — the broker SPI (`spi/broker`), the shared config (`common`), the relay mechanism+wiring (`runtime/relay`), the broker-common + rocketmq impl (`runtime/transport/broker/{,rocketmq/}`) all live forwarding-internal. Top-level `common/` + `eventbus.runtime/` planes are eliminated. Future wiring files land in their forwarding sub-package, not as top-level planes.
- **New invariant (plane boundary, narrower):** the gateway process form never reaches into the event-bus relay mechanism/wiring (`forwarding.runtime.relay`) — ArchUnit-enforced (`gateway.runtime.. ↛ forwarding.runtime.relay..`). The gateway legitimately wires the broker adapters + jdbc outbox + transport (SDK surface) as a producer/consumer. A stricter rule (gateway↛forwarding.runtime via auto-config) is a flagged follow-on.
- **SDK boundary (Q4, package-set under Q1=b):** the producer/consumer SDK = `forwarding/spi` + `forwarding/spi/broker` + `forwarding/common` + `forwarding/runtime/{relay, transport/{a2a, broker}, persistence/jdbc}`. The process packages (`gateway/runtime/` + the relay wiring in `forwarding/runtime/relay/`) add their `@Configuration` + Spring boot on top of the SDK.
- **Component scan unchanged:** `AgentBusApplication` (plain `@SpringBootApplication` in `com.huawei.ascend.bus`) default-scans `com.huawei.ascend.bus..`; the new `forwarding/{common,spi/broker,runtime/transport/broker/rocketmq}` are auto-covered. No `@ComponentScan` change.
- **No behaviour/profile/bean-name/build change:** the refactor is a package re-organisation + ArchUnit-rule evolution. `@Profile`, bean names/qualifiers, Spring 7 idioms, the `spring-boot-maven-plugin repackage` + `@Profile` build mechanism are unchanged. 11 source files moved + 5 test files moved (build-forced by package-private access) + 4 ArchUnit tests evolved + import ripple.
- **ADR-0162 superseded:** 0162's top-level-plane layering (`eventbus.runtime`/`common`) + `gateway↛eventbus` rule are superseded by this forwarding-centric layering + the `gateway↛forwarding.runtime.relay` rule. 0162's other content (the agent-bus-layering refactor mechanics) stays as historical record.
- **NOT a REQ-2026-001 release blocker** (pure package re-org + ArchUnit-rule evolution; release bar = InMemoryBroker CI gate + real RocketMQ env-guarded + TestAgentRuntime E2E, none require the layering).
