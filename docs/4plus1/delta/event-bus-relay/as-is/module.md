# as-is module view — agent-bus plane

The single `AgentBusApplication` boots **only the registry plane**: five Spring beans, all in `registry.runtime` (`MvpRegistryController` `@RestController`, `MvpHealthProbeScheduler` `@Component` `@Scheduled`, `PgMvpDiscoveryServiceImpl` `@Service`, `RegistrySchedulingConfig`/`RegistryObservabilityConfig` `@Configuration`, one `@Bean` for the probe scheduler). Component-scan is `com.huawei.ascend.bus..`, but nothing in `forwarding/**` or `gateway/**` is annotated — so the scan finds **no** forwarding/gateway beans.

The entire **forwarding + gateway + broker substrate is library code with zero Spring wiring**: `GatewayRuntimeService`, `ForwardingDispatcherWorker`/`ForwardingDispatchLoop`, the JDBC persistence (`JdbcForwardingOutbox`/`JdbcForwardingInbox`), the broker adapters (`RocketMqBrokerForwardingRelay`/`RocketMqBrokerForwardingConsumer`), and `A2aForwardingDeliveryPort` are plain POJOs. Verified by grep: `new GatewayRuntimeService(...)`, `new ForwardingDispatcherWorker(...)`, `new ForwardingDispatchLoop(...)`, `new A2aForwardingDeliveryPort(...)` appear **only in tests** (`InMemoryBroker`, `TestAgentRuntime`, `FakeConsumer`/`InMemoryForwardingDelivery`, the LitePull IT adapters). `GatewayRuntimeService.dispatchRequest` produces inline (synchronous) bypassing the worker entirely.

The existing worker/loop are **producer-shape** (claim own outbox → `ForwardingDeliveryPort.deliver`); there is **no consume→govern→re-produce relay component**. `A2aForwardingDeliveryPort` is the only `ForwardingDeliveryPort` impl — the Stage-15 T1 HTTP push the to-be replaces.

Deployment: no `spring-boot-maven-plugin <repackage>` in any module (root pom only `pluginManagement` config; `agent-bus/pom.xml` has no `<build>` section; agent-runtime explicitly "plain library") → `AgentBusApplication`'s "java -jar" claim is unfulfillable (only `spring-boot:run` boots the registry). `docker-compose.yml` runs RocketMQ-only (nameserver + broker + init provisioning the 8 L2 topics). Root `Dockerfile` builds agent-runtime as a `CMD ["java","-version"]` library-carrier image — no agent-bus/gateway/event-bus image.

**Why this matters (carries into to-be):** the net-new is not "assemble a relay" alone — it is *wire the gateway + forwarding substrate into two runnable process forms* (gateway / event-bus+registry), with a new consume→govern→re-produce relay in the event-bus form, plus deployment artifacts. The "library jar" KF-1 positioning ADR-0160 partially superseded (registry now boots) but the gateway/forwarding/runtime split was never wired.
